# Архитектура и границы доверия

## Поток данных

`input → propose(State, text) → Proposal → selected fields → proposedProject → review → apply → LocalStore.save → render`

`State` — применённый проект, ревизия, журнал и стек отмены. `Proposal` — отдельный объект с базовой ревизией, объяснением, составом модулей и отличиями. Предпросмотр строится из `State + selected changes`; экспорт берёт только `State.project`. Ручной ввод, импорт и отметка задачи проходят ту же границу подтверждения.

## Модули

- `model.ts`: чистая модель, валидация, ограниченный разбор намерения, diff/apply/undo.
- `storage.ts`: IndexedDB, одно атомарное readwrite-сохранение с проверкой ревизии. Отдельные вкладки не синхронизируются автоматически: устаревшая запись отклоняется.
- `composer.ts`, `lab.ts`: самостоятельные Web Components с обычным DOM. Shadow DOM намеренно не нужен для этого общего визуального языка.
- `modules.ts`, `review.ts`: функции отображения доверенного набора компонентов. Пользовательские строки экранируются.
- `app.ts`: оболочка, маршруты через hash, orchestration, явное управление состояниями загрузки/ошибки.
- `evidence.ts`: данные первоисточников. Не подгружаются с внешнего сервера.
- `ui.ts`: общий рендер иконок, безопасное отображение текста, локальный экспорт, optional View Transitions с reduced-motion fallback.

Нет `eval`, `new Function`, исполняемого пользовательского HTML или произвольной схемы компонентов. Это ограничение поверхности исполнения, **не доказательство абсолютной безопасности**. Внедрение настоящей модели потребует серверной границы доверия, проверки действий и отдельного анализа угроз.

## Сохранение и отказоустойчивость

IndexedDB хранит один версионированный документ. Журнал ограничен 40 событиями, отмена — 20 снимками. Это учебная модель небольшого проекта, не масштабируемая система совместной работы. Идентификатор события — локальная метка, не идентификатор для авторизации.

При первоначальной недоступности или повреждении хранилища приложение показывает постоянное предупреждение и работает в памяти, не перезаписывая повреждённые данные. При неудаче сохранения во время сеанса изменение не объявляется сохранённым. Сохраняется только последний применённый проект; черновики и результаты микроэксперимента автоматически не сохраняются.

Необходимо экспортировать JSON для резервного копирования. Нет шифрования, аккаунтов, облачной копии, восстановления удалённого профиля, CRDT или разрешения конфликтов путём слияния. Подтверждённые значения другого устройства не проверяются: устройств в модели нет.

## Сборка и переносимость

`tsc` компилирует ESM. Build-скрипт копирует статические файлы и дополнительно объединяет **известный** модульный граф в один HTML. Это небольшой сборщик конкретного приложения, не универсальный bundler; при новых модулях нужно обновить массив `moduleNames` и тестировать обе поставки.

Service worker кэширует оболочку при установке и отдаёт кэш при сетевом отказе. Нужны HTTPS или localhost и успешное первое открытие с установкой кэша. Standalone HTML включает CSS/JS и не регистрирует worker. Поддержка browser storage на `file://` не гарантирована: доступен явный memory fallback.

CSS View Transitions используются только при наличии API, reduced-motion учитывается. Нет внешних шрифтов, аналитики или CDN. Переход по ссылке первоисточника, естественно, открывает внешний сайт.

## Что потребуется для реального агентного продукта

Модель или инструмент должны отдавать строго проверяемую структуру предложения. На сервере нужно проверять пользователя, доступ к ресурсу, допустимость операции, идемпотентность, срок действия и исходную ревизию. UI-подтверждение не заменяет авторизацию. Проект из JSON, текст книги и результаты инструментов следует считать недоверенными данными, не инструкциями.

Для внешних действий нужны конкретный адресат/ресурс/сумма, отдельное подтверждение необратимого последствия и реальное состояние операции. «Отмена» локального состояния не отменяет отправленное письмо или перевод денег. Не обещать rollback там, где возможна только компенсирующая операция. Не хранить API-ключи в клиентском коде.

A2UI, WebMCP, LLM, многопользовательский сервер и платёжные интеграции здесь **не реализованы**. Разделение модели и рендера позволяет исследовать их позже без заявления о готовой интеграции.
